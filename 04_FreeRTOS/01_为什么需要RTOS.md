# 为什么需要 RTOS

## 1. 本节要解决什么问题

很多同学刚学单片机时，程序都是 `while (1)` 加各种函数轮询。项目简单时可以工作，但任务一多，就会出现响应慢、代码乱、调试困难。

本节要解决的问题是：为什么嵌入式项目需要 RTOS，以及 FreeRTOS 能解决什么问题。

## 2. 基本概念

RTOS 是实时操作系统。FreeRTOS 是嵌入式领域常用的轻量级 RTOS。

它提供：

- 任务；
- 优先级；
- 队列；
- 信号量；
- 互斥量；
- 软件定时器；
- 任务延时和调度。

RTOS 不是为了让系统变复杂，而是为了把多个同时发生的事情拆开管理。

## 3. 为什么嵌入式项目需要它

以 RS485/Modbus 控制项目为例，系统可能同时需要：

- 采集传感器；
- 接收串口数据；
- 解析 Modbus 帧；
- 控制电机或执行器；
- 保存日志；
- 与 Qt 上位机通信；
- 处理按键和状态灯。

如果全部塞进一个 `while (1)`，代码会越来越难维护。FreeRTOS 可以把这些工作拆成多个任务，让每个任务只负责一类事情。

## 4. 工程使用场景

一个简化的任务划分：

```text
采集任务      周期读取传感器
通信任务      接收和解析 RS485/Modbus 帧
控制任务      根据参数和状态输出控制量
日志任务      保存关键事件和错误码
上位机任务    处理参数配置和状态上传
```

涉及传感器、驱动器、控制卡等真实硬件时，采样周期、控制周期、通信参数、接线和端子定义必须以数据手册、端子定义、原理图或实测结果为准。

## 5. 代码示例

下面是一个非常简化的 FreeRTOS 任务划分示例：

```c
void task_sensor(void *argument)
{
    while (1) {
        sensor_sample_once();
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

void task_modbus(void *argument)
{
    while (1) {
        if (modbus_receive_frame()) {
            modbus_parse_and_reply();
        }

        vTaskDelay(pdMS_TO_TICKS(1));
    }
}

void task_control(void *argument)
{
    while (1) {
        control_update_output();
        vTaskDelay(pdMS_TO_TICKS(5));
    }
}
```

这个例子不是完整项目，但能体现一个思想：把采集、通信、控制分开。

## 6. 常见错误

- 以为用了 RTOS 就一定实时。任务优先级、阻塞时间和临界区设计不对，照样不实时。
- 高优先级任务里写死循环，不让低优先级任务运行。
- 多任务共享变量没有互斥保护。
- 任务栈太小，运行一段时间后异常。
- 在中断里调用不适合中断环境的 API。

## 7. 调试方法

- 观察每个任务是否周期运行。
- 检查任务栈剩余空间。
- 统计队列长度和丢消息次数。
- 给关键任务加心跳计数。
- 用日志记录任务超时、通信错误和控制状态变化。

## 9. 简历表达方式

可以写：

> 基于 FreeRTOS 进行任务划分，将传感器采集、RS485/Modbus 通信和控制逻辑拆分为独立任务，并使用队列传递通信事件，提高系统可维护性和响应性。

## 10. 小练习

1. 把一个裸机 `while (1)` 程序拆成 3 个任务。
2. 设计通信任务和控制任务之间的消息结构。
3. 思考哪个任务优先级最高，为什么。
4. 给每个任务设计一个心跳变量。
5. 查 FreeRTOS 文档，区分队列、信号量和互斥量。

## 11. 小结

RTOS 的价值不是“简历上多一个关键词”，而是帮助你管理复杂系统。能讲清楚任务拆分、通信任务、控制任务、队列和调试方法，才说明你真的理解 FreeRTOS。
