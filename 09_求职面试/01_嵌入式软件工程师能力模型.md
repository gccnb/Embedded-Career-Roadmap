# 嵌入式软件工程师能力模型

## 1. 本节要解决什么问题

准备嵌入式软件岗位时，很多同学不知道自己到底差在哪里。简历上写了 C、STM32、FreeRTOS、Modbus，但面试官一追问项目细节，就回答不深入。

本节要解决的问题是：嵌入式软件工程师岗位到底看哪些能力。

## 2. 基本概念

可以把嵌入式软件能力分成 6 层：

1. C 语言和数据结构基础；
2. 单片机外设和硬件接口；
3. 通信协议和数据解析；
4. RTOS 或 Linux 系统能力；
5. 调试、测试和问题定位；
6. 项目表达和工程文档。

初学者不要只盯着某个芯片型号。岗位真正看重的是你能否把一个功能从需求做到可验证。

## 3. 为什么嵌入式项目需要它

一个项目从来不是单点知识：

- C 语言决定代码可靠性；
- 外设决定硬件能不能驱动；
- 协议决定设备之间能不能通信；
- RTOS 决定多任务是否清晰；
- 调试能力决定问题能不能解决；
- 表达能力决定面试官能不能相信你做过。

这些能力组合起来，才是嵌入式软件工程师的核心竞争力。

## 4. 工程使用场景

以 RS485/Modbus + Qt 上位机项目为例：

- C 语言：实现缓冲区、CRC、状态机；
- 单片机：配置 USART、GPIO、定时器；
- 协议：解析 Modbus RTU 帧；
- RTOS：拆分通信任务和采集任务；
- Qt：做调试界面和日志；
- 调试：分析超时、CRC 错误、接线问题。

涉及真实设备时，硬件参数、接线、端子、寄存器含义必须以数据手册、端子定义、原理图或实测结果为准。

## 5. 代码示例

能力模型也可以落到代码组织上：

```c
typedef enum {
    COMM_OK = 0,
    COMM_TIMEOUT,
    COMM_CRC_ERROR,
    COMM_LENGTH_ERROR
} CommStatus;

typedef struct {
    unsigned int ok_count;
    unsigned int timeout_count;
    unsigned int crc_error_count;
} CommStatistic;

static CommStatistic g_comm_stat;

void comm_record_status(CommStatus status)
{
    if (status == COMM_OK) {
        g_comm_stat.ok_count++;
    } else if (status == COMM_TIMEOUT) {
        g_comm_stat.timeout_count++;
    } else if (status == COMM_CRC_ERROR) {
        g_comm_stat.crc_error_count++;
    }
}
```

这个例子说明：工程代码不仅要完成通信，还要留下统计和调试信息。

## 6. 常见错误

- 简历关键词很多，但项目没有闭环。
- 只写“熟悉某芯片”，说不出具体外设和调试问题。
- 只会背面试题，不会结合项目回答。
- 项目描述夸大，比如写“已应用于工业现场”，但没有真实依据。
- 忽略文档和日志，导致面试时讲不清过程。

## 7. 调试方法

能力提升也需要调试：

- 用项目复盘表记录问题和解决过程；
- 每个模块留下测试输入和输出；
- 对通信问题保存原始报文；
- 对硬件问题保存手册依据和实测截图；
- 每周把技术点改写成面试回答。

## 8. 面试常问问题

1. 你最熟悉的嵌入式项目是什么？
2. 这个项目中你负责哪一部分？
3. 遇到最难的问题是什么，怎么定位？
4. 为什么使用 RS485 或 Modbus？
5. 如果通信偶发失败，你怎么排查？
6. FreeRTOS 任务是怎么划分的？

## 9. 简历表达方式

一段好的项目描述应包含：

- 项目目标；
- 你的职责；
- 使用的技术；
- 关键实现；
- 调试和验证；
- 可公开的结果。

示例：

> 设计并实现嵌入式设备通信调试项目，负责单片机端 RS485/Modbus RTU 通信、CRC16 校验、寄存器表设计和 Qt 上位机联调，完成异常帧、超时和通信日志记录。

## 10. 小练习

1. 给自己按 6 层能力打分。
2. 写出一个项目中你真正独立完成的 3 个模块。
3. 准备一个“通信失败如何排查”的回答。
4. 把一个课程设计改写成工程项目描述。
5. 删除简历中无法解释或无法验证的夸大表述。

## 11. 小结

嵌入式软件工程师能力不是关键词列表，而是从代码、硬件、协议、系统、调试到表达的完整闭环。

求职时，你要让面试官看到：你能做项目，能查问题，能讲清楚，也知道工程边界。
