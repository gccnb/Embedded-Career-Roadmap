# 项目复盘模板

## 1. 本节要解决什么问题

本节要解决的问题是：做完一个嵌入式项目后，如何整理成面试能讲、简历能写、自己也能复盘的材料。

很多同学项目做过，但面试时讲不清楚。原因通常不是没写代码，而是没有提前整理：项目目标是什么、你负责什么、技术方案怎么选、遇到什么问题、怎么定位、结果怎么验证。

项目复盘模板的作用是把“做过”变成“讲得清楚”。

## 2. 基本概念

一份合格的项目复盘至少包含：

| 部分 | 要回答的问题 |
|---|---|
| 项目背景 | 为什么做这个项目 |
| 项目目标 | 最终要实现什么功能 |
| 技术方案 | 用了哪些模块和为什么 |
| 个人职责 | 你具体完成了什么 |
| 调试问题 | 遇到哪些真实问题 |
| 解决过程 | 怎么定位和验证 |
| 结果证据 | 有哪些代码、日志、测试用例 |
| 简历表达 | 如何写成一条项目经历 |
| 面试讲法 | 如何用 1 分钟讲清楚 |

复盘不是包装，也不是夸大。学习项目就写学习项目，个人项目就写个人项目。

## 3. 工程用途

项目复盘能帮助你建立工程表达能力。比如 RS485/Modbus 项目，不要只说“实现通信”，而要说：

- 下位机怎么接收和解析；
- CRC 怎么校验；
- 03/06 功能码怎么处理；
- Qt 上位机怎么显示 TX/RX；
- 发生超时、CRC 错误、非法地址时怎么排查；
- 哪些日志能证明你调试过。

这类表达能直接服务面试和简历。

## 5. 常见错误

- 只写“实现了某功能”，没有说明如何验证。
- 把学习项目写成真实公司项目。
- 没有日志和测试用例，面试追问时只能凭印象回答。
- 技术栈堆太多，但每个都讲不深。
- 难点写成“代码比较复杂”，没有具体问题。
- 解决过程没有证据，比如没有原始帧、错误码、截图或测试记录。

## 6. 调试复盘写法

推荐使用“现象 -> 分层排查 -> 证据 -> 结论”的结构。

示例：

```text
现象：
Qt 上位机发送 03 请求后没有响应。

分层排查：
1. 查串口是否打开，确认 QSerialPort 返回成功。
2. 查 TX 日志，确认请求帧已发送。
3. 用串口助手对比请求帧，确认 CRC 字节顺序。
4. 查下位机接收日志，发现从机地址不匹配。

证据：
TX: 01 03 00 00 00 02 C4 0B
MCU log: addr mismatch, local addr=02

结论：
上位机从机地址配置错误，不是 RS485 接线问题。
```

## 7. 面试常问问题

1. 问：你这个项目最大的难点是什么？
   答：不要回答“代码复杂”。应回答一个具体问题，比如 RS485 方向切换、CRC 字节顺序、Qt 串口异步接收、状态字解析等。

2. 问：你怎么证明项目真的跑通过？
   答：展示测试用例、TX/RX 原始日志、解析结果和异常测试记录。

3. 问：如果没有真实设备，这个项目还有价值吗？
   答：有。它训练协议解析、通信调试、日志复盘和上位机联调能力。但要诚实说明使用模拟寄存器和抽象状态。

4. 问：项目里你最能体现工程能力的地方是什么？
   答：可以讲模块边界、错误处理、日志记录、测试用例和问题定位过程。

5. 问：如果让你继续完善，你会做什么？
   答：可以说增加 FreeRTOS 任务拆分、Qt 日志导出、更多异常响应、自动化测试或真实硬件验证。

## 8. 简历表达方式

复盘后的简历表达要具体：

```text
个人项目：RS485/Modbus RTU 通信调试系统。
基于单片机实现 Modbus RTU 从机解析，支持 03 读保持寄存器、06 写单个寄存器、CRC16 校验和模拟寄存器表；基于 Qt 上位机实现串口配置、请求帧生成、响应解析和 TX/RX 日志导出；设计 CRC 错误、非法地址、超时等测试用例完成联调复盘。
```

不要写：

```text
参与工业控制项目，实现稳定运行。
```

如果没有真实、可公开、可证明的项目背景，这种写法风险很高。

## 9. 小练习

1. 用本模板复盘 `Modbus RTU 设备调试项目`。
2. 写出一个你遇到的通信问题，按“现象、验证、结论”整理。
3. 把项目复盘压缩成 1 分钟面试讲法。
4. 从复盘中提炼 1 条简历项目经历。

## 10. 小结

项目复盘的目标是让项目经得住追问。代码、日志、测试用例、问题定位过程和边界说明都要清楚。对嵌入式求职来说，复盘能力本身就是工程能力的一部分。
