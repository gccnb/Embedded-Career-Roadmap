# 简历项目描述模板

## 1. 本节要解决什么问题

很多同学明明做过项目，但简历写成了“使用 STM32、FreeRTOS、Modbus、Qt 完成系统设计”。这句话看起来有很多关键词，但面试官看不出你到底做了什么。

本节要解决的问题是：如何把嵌入式项目写成清楚、可信、可追问的简历描述。

## 2. 基本概念

项目描述不是宣传语，而是工程经历摘要。

一段好的项目描述通常包含：

- 项目背景；
- 技术栈；
- 个人职责；
- 关键实现；
- 调试验证；
- 可公开成果。

不要编造真实公司项目、客户信息、量产结果或性能指标。没有验证过的成果不要写成确定结论。

## 3. 为什么嵌入式项目需要它

嵌入式岗位面试很重视项目追问。面试官会从简历里挑一个词继续问：

- 你说会 Modbus，那帧格式是什么？
- 你说做过 RS485，那方向控制怎么处理？
- 你说用了 FreeRTOS，任务怎么划分？
- 你说做了上位机，日志怎么保存？

如果简历写得太虚，反而会暴露准备不足。

## 4. 工程使用场景

适合写进简历的项目包括：

- 单片机传感器采集与 RS485 上传；
- Modbus RTU 主站或从站通信；
- FreeRTOS 多任务控制系统；
- Qt 串口调试上位机；
- 工业控制或机器视觉控制系统的抽象练习项目。

涉及硬件接线、端子、驱动器、传感器、控制卡时，简历和项目文档都应说明“依据数据手册、端子定义、原理图或实测结果完成确认”，不要写无法证明的现场结论。

## 5. 代码示例

简历不是放大段代码，但可以在项目仓库中准备核心代码片段。比如 CRC 校验、帧解析、寄存器表：

```c
typedef struct {
    unsigned short address;
    unsigned short value;
    unsigned char writable;
} RegisterItem;

static RegisterItem g_registers[] = {
    {0x0000, 0, 0},
    {0x0001, 0, 1},
    {0x0002, 0, 0}
};

int register_write(unsigned short address, unsigned short value)
{
    unsigned char i;

    for (i = 0; i < 3; i++) {
        if (g_registers[i].address == address) {
            if (g_registers[i].writable == 0) {
                return 0;
            }
            g_registers[i].value = value;
            return 1;
        }
    }

    return 0;
}
```

这类代码能支撑你讲清楚“寄存器表”和“读写权限”。

## 6. 常见错误

- 写“负责整个系统”，但实际只做了很小一部分。
- 写“精通”，但无法回答细节。
- 写“工业级”“量产级”，但没有测试和交付依据。
- 只列技术栈，不写关键实现。
- 不写调试问题，导致项目显得像复制教程。

## 7. 调试方法

简历项目也要调试表达：

- 对每个项目准备 1 分钟版本和 3 分钟版本。
- 每个技术关键词准备一个追问回答。
- 每个项目至少准备一个真实调试问题。
- 删除不能解释的词。
- 把“我参与了”改成“我负责实现了某模块”。

## 8. 面试常问问题

1. 这个项目为什么要做？
2. 你负责哪一部分？
3. RS485 通信怎么调通的？
4. Modbus CRC 错误你怎么定位？
5. 上位机和下位机如何联调？
6. 这个项目还有哪些不足？

## 9. 简历表达方式

推荐模板：

```text
项目名称：基于单片机的 RS485/Modbus RTU 通信与 Qt 上位机调试系统

项目描述：
面向嵌入式设备通信调试场景，设计单片机端寄存器表和 Modbus RTU 通信流程，
实现保持寄存器读取、参数写入、CRC16 校验、异常响应和通信日志记录。

个人职责：
1. 实现 USART 接收缓冲区和 RS485 半双工方向控制；
2. 实现 Modbus RTU 帧解析、CRC 校验和寄存器读写；
3. 使用 Qt 上位机进行串口参数配置、报文发送、响应显示和日志保存；
4. 记录并分析超时、CRC 错误、帧长度异常等调试问题。
```

如果项目只是学习项目，就写“学习项目”或“个人项目”，不要暗示真实商业交付。

## 10. 小练习

1. 用上面的模板写一个你自己的项目。
2. 删除项目描述中所有无法证明的形容词。
3. 给每个技术关键词准备一个追问回答。
4. 写一个项目中的调试问题和解决过程。
5. 把项目描述压缩到 3 行以内。

## 11. 小结

简历项目描述要真实、具体、可追问。对于嵌入式软件岗位，最有价值的不是堆技术名词，而是讲清楚通信链路、关键代码、调试方法和验证过程。

真实经历不夸大，学习项目不包装，工程能力讲扎实，这样的简历更经得起面试。
