# 通信工程硕士转嵌入式软件工程师学习路线

## 1. 本节要解决什么问题

很多通信工程硕士同学学过信号、通信原理、数字电路、C 语言和一些 MATLAB 仿真，但真正投嵌入式软件岗位时，会发现简历上缺少“可运行、可调试、可解释”的工程项目。

本节要解决的问题是：如何把通信工程背景转成嵌入式软件岗位认可的能力。

你可以把目标拆成三句话：

- 能写单片机程序；
- 能处理通信协议；
- 能把项目调通并讲清楚。

## 2. 基本概念

嵌入式软件工程师不是只写 C 语言的人，而是负责让软件在具体硬件和具体场景中稳定工作的人。

常见工作内容包括：

- 控制 GPIO、定时器、ADC、PWM、USART 等外设；
- 编写串口、RS485、CAN、SPI、I2C 等通信代码；
- 解析自定义协议、Modbus RTU、设备寄存器表；
- 在 FreeRTOS 或 Linux 下拆分任务和处理并发；
- 配合上位机、测试工具、示波器、逻辑分析仪定位问题；
- 写调试记录、接口文档、测试说明和项目总结。

通信工程背景的优势在于：你理解通信链路、噪声、编码、调制、系统建模。转嵌入式时，要把这些优势落到“串口收发稳定、协议解析可靠、现场问题能定位”上。

## 3. 为什么嵌入式项目需要它

企业招聘嵌入式软件工程师时，看重的不只是“学过什么”，而是“能不能把设备跑起来”。

例如一个工业控制或机器视觉控制系统，可能包含：

- 下位机采集传感器信号；
- 控制器通过 RS485 与驱动器通信；
- 上位机通过 Qt 配置参数、显示日志；
- 通信协议使用自定义帧或 Modbus RTU；
- 多个任务需要在 FreeRTOS 中协作。

这类项目要求你既懂代码，也懂调试，还能解释为什么这么设计。

## 4. 工程使用场景

建议用一个贯穿项目作为学习主线：

“基于 STM32 的 RS485/Modbus 设备通信与 Qt 上位机调试系统”。

这个项目可以抽象成：

- 单片机负责串口接收、协议解析、寄存器读写；
- RS485 负责长距离半双工通信；
- Modbus RTU 负责标准化读写寄存器；
- FreeRTOS 负责拆分采集任务、通信任务、日志任务；
- Qt 上位机负责发送命令、显示响应、保存调试日志。

涉及真实硬件接线时，必须以数据手册、端子定义、原理图或实测结果为准，不能凭经验猜测 A/B 线、方向控制脚、电源和地线。

## 5. 代码示例

先用一个非常小的学习项目建立主线意识：

```c
typedef struct {
    unsigned short temperature;
    unsigned short speed;
    unsigned short status;
} DeviceRegisterMap;

static DeviceRegisterMap g_regs;

void app_update_temperature(unsigned short value)
{
    g_regs.temperature = value;
}

unsigned short app_read_register(unsigned short address)
{
    switch (address) {
    case 0x0000:
        return g_regs.temperature;
    case 0x0001:
        return g_regs.speed;
    case 0x0002:
        return g_regs.status;
    default:
        return 0;
    }
}
```

这个例子虽然简单，但已经接近 Modbus 项目的核心：设备内部有一张寄存器表，上位机通过通信协议读取或修改这些值。

## 6. 常见错误

- 只学语法，不做项目，面试时讲不出调试过程。
- 简历写“熟悉 Modbus”，但说不清帧格式、CRC、异常响应。
- 会用串口发送数据，但不知道超时、粘包、半包、缓冲区溢出怎么处理。
- 做项目时不写调试记录，最后无法总结成简历亮点。
- 把课程设计包装成真实交付项目，面试被追问时容易露馅。

## 7. 调试方法

学习路线中的每个阶段都要配合调试工具：

- 单片机阶段：用 LED、串口打印、断点、变量观察；
- 串口阶段：用串口助手、逻辑分析仪、USB-RS485 模块；
- Modbus 阶段：保存十六进制报文，逐字节核对功能码和 CRC；
- FreeRTOS 阶段：观察任务优先级、栈空间、队列长度和超时；
- Qt 阶段：保存日志，记录发送时间、响应时间和错误原因。

调试不是项目后期才做的事，而是从第一行代码开始就要设计进去。

## 8. 面试常问问题

1. 通信工程专业为什么转嵌入式软件？
2. 你做过的嵌入式项目中，最核心的通信链路是什么？
3. RS485 和 UART 有什么区别？
4. Modbus RTU 一帧包括哪些字段？
5. 串口接收中断里为什么不能做太多事情？
6. FreeRTOS 中任务优先级如何设计？
7. 你如何定位通信偶发丢包或 CRC 错误？

回答时要少说“我学习了”，多说“我实现了什么、怎么验证、遇到什么问题、怎么解决”。

## 9. 简历表达方式

可以这样表达：

> 基于单片机实现 RS485/Modbus RTU 通信模块，完成寄存器读写、CRC16 校验、串口中断接收和异常帧处理；配合 Qt 上位机进行协议联调，记录并分析通信超时、CRC 错误和参数下发问题。

这句话的重点是：模块、协议、调试、问题分析。它比“熟悉 STM32、熟悉 Modbus”更像工程经历。

## 10. 小练习

1. 写出你当前已经掌握的 5 个知识点。
2. 写出你离嵌入式软件岗位还缺的 5 个能力。
3. 用 100 字描述一个你想做的 RS485/Modbus 项目。
4. 设计一张 3 个寄存器的设备寄存器表。
5. 用串口助手发送一帧十六进制数据，并记录发送和接收结果。

## 11. 小结

通信工程转嵌入式软件，不是从零开始。你需要做的是把专业背景落到单片机、通信协议、实时任务、上位机联调和项目表达上。

学习主线要清楚：单片机基础 -> 嵌入式 C -> USART/RS485 -> 自定义协议 -> Modbus RTU -> FreeRTOS -> C++ -> Linux -> Qt 上位机 -> 项目实战 -> 求职面试。

每走一步，都要留下代码、调试记录和简历表达。
