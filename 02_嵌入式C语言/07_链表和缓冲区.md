# 链表和缓冲区

## 1. 本节要解决什么问题

嵌入式项目中经常要处理连续到来的数据，比如串口字节流、日志记录、传感器采样值和协议帧。很多初学者会直接用数组硬塞，数据一多就出现丢包、越界和解析混乱。

本节要解决的问题是：什么时候用缓冲区，什么时候了解链表，以及求职项目中该怎么讲。

## 2. 基本概念

缓冲区是一块临时存放数据的内存。串口接收、协议解析、日志输出都会用到。

常见缓冲区：

- 普通数组缓冲区；
- 环形缓冲区；
- 双缓冲；
- DMA 接收缓冲区。

链表是一种通过指针把多个节点连接起来的数据结构。它适合动态插入和删除，但在资源紧张的单片机中要谨慎使用。

## 3. 为什么嵌入式项目需要它

串口和 RS485 通信是典型的字节流场景。数据可能一个字节一个字节来，也可能被中断、DMA、空闲中断分批送到程序中。

如果没有缓冲区，程序很容易出现：

- 中断里处理太久，后续字节丢失；
- 主循环还没解析完，新数据已经覆盖旧数据；
- 半包、粘包无法处理；
- 日志和通信互相阻塞。

链表在嵌入式里不是不能用，而是要清楚代价：动态内存、碎片、节点管理和调试复杂度。

## 4. 工程使用场景

- USART 中断接收：用环形缓冲区保存字节。
- Modbus RTU 接收：用定时或空闲中断判断一帧结束。
- 日志系统：用队列或缓冲区缓存待输出日志。
- FreeRTOS 项目：用队列在通信任务和业务任务之间传递消息。
- Qt 上位机：用接收缓冲区拼接串口分段返回的数据。

涉及真实设备通信时，协议帧长度、超时时间、波特率、端子接线都要以数据手册、端子定义、原理图或实测结果为准。

## 5. 代码示例

环形缓冲区比链表更常用于单片机串口接收：

```c
#define RING_SIZE 256

typedef struct {
    unsigned char data[RING_SIZE];
    unsigned short read;
    unsigned short write;
} RingBuffer;

static RingBuffer g_uart_ring;

int ring_push(RingBuffer *ring, unsigned char byte)
{
    unsigned short next = (ring->write + 1) % RING_SIZE;

    if (next == ring->read) {
        return 0;
    }

    ring->data[ring->write] = byte;
    ring->write = next;
    return 1;
}

int ring_pop(RingBuffer *ring, unsigned char *byte)
{
    if (ring->read == ring->write) {
        return 0;
    }

    *byte = ring->data[ring->read];
    ring->read = (ring->read + 1) % RING_SIZE;
    return 1;
}
```

这个例子要重点理解两个判断：读写指针相等表示空，写指针再前进一步等于读指针表示满。

## 6. 常见错误

- 缓冲区满时继续写，导致覆盖未处理数据。
- 忘记对读写指针取模。
- 中断和主循环同时修改指针，但没有考虑临界区。
- 用链表频繁 `malloc` 和 `free`，长期运行后出现内存碎片。
- 协议解析时没有检查帧长度，直接访问数组。

## 7. 调试方法

- 打印读指针、写指针和当前缓存字节数。
- 用串口助手发送固定帧，确认每个字节都进入缓冲区。
- 故意发送超长数据，观察是否能正确丢弃或报错。
- 对 Modbus 帧保存十六进制日志，检查是否发生半包或粘包。
- 在 FreeRTOS 中观察队列长度和任务执行周期。

## 8. 面试常问问题

1. 环形缓冲区如何判断空和满？
2. 为什么串口中断里不建议直接解析完整协议？
3. 单片机里为什么要谨慎使用链表和动态内存？
4. 半包和粘包是什么？
5. 如何防止缓冲区溢出？

## 9. 简历表达方式

可以写：

> 设计串口环形缓冲区处理 RS485 字节流，支持半包缓存、完整帧提取和缓冲区溢出保护，提高 Modbus RTU 通信解析的稳定性。

这句话能体现你理解数据流，而不是只会调用串口发送函数。

## 10. 小练习

1. 写一个 256 字节环形缓冲区。
2. 增加一个函数返回当前缓存长度。
3. 设计一个策略：缓冲区满时丢新数据还是丢旧数据？
4. 用固定数组模拟 3 帧 Modbus 数据的接收过程。
5. 思考在 FreeRTOS 中是否可以用队列替代一部分缓冲区逻辑。

## 11. 小结

缓冲区是嵌入式通信项目的基础能力。链表是重要数据结构，但在资源受限、实时性要求高的单片机项目中要谨慎使用。

求职时，能讲清楚环形缓冲区、串口接收、半包粘包和溢出保护，会比单纯背链表定义更有价值。
