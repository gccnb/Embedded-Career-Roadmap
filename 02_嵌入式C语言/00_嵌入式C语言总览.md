# 嵌入式 C 语言总览

## 1. 本节要解决什么问题

很多同学学过 C 语言课程，但一进入嵌入式项目就会发现：项目里的 C 语言不是刷题风格，而是和寄存器、外设、中断、缓冲区、协议解析紧密绑在一起。

本节要解决的问题是：嵌入式 C 到底应该重点学什么。

## 2. 基本概念

嵌入式 C 是运行在具体硬件上的 C 语言。它不仅关心算法结果，还关心：

- 变量放在哪里；
- 中断什么时候修改变量；
- 缓冲区是否越界；
- 一个字节的每一位代表什么；
- 函数是否会阻塞；
- 代码是否方便调试和维护。

学习嵌入式 C，要特别重视指针、数组、结构体、位运算、枚举、宏、`static`、`extern`、`const`、`volatile`、环形缓冲区和状态机。

## 3. 为什么嵌入式项目需要它

在 RS485/Modbus 项目里，C 语言会直接决定通信是否可靠：

- 串口中断收到的字节要放进缓冲区；
- 主循环或任务要从缓冲区取出一帧；
- 协议解析要判断地址、功能码、长度和 CRC；
- 寄存器表要用结构体或数组管理；
- 状态变量可能被中断和主程序同时访问。

如果 C 语言基础不扎实，问题通常不是编译不过，而是偶发死机、数据错位、CRC 错误、数组越界、任务卡死。

## 4. 工程使用场景

嵌入式 C 常见场景包括：

- 用结构体描述设备参数；
- 用枚举描述协议状态；
- 用位运算处理状态字和控制字；
- 用环形缓冲区接收串口数据；
- 用 `volatile` 标记中断修改的标志位；
- 用 `static` 限制模块内部变量作用域；
- 用 `const` 保存协议表、命令表、字符串表。

涉及芯片寄存器或外设初始化时，要以芯片参考手册、HAL 文档、BSP 示例和实测结果为准，不要凭经验写寄存器位。

## 5. 代码示例

下面是一个简化的串口接收缓冲区示例：

```c
#define RX_BUFFER_SIZE 128

static unsigned char g_rx_buffer[RX_BUFFER_SIZE];
static volatile unsigned short g_write_index = 0;
static unsigned short g_read_index = 0;

void uart_rx_isr(unsigned char byte)
{
    unsigned short next = (g_write_index + 1) % RX_BUFFER_SIZE;

    if (next != g_read_index) {
        g_rx_buffer[g_write_index] = byte;
        g_write_index = next;
    }
}

int uart_read_byte(unsigned char *byte)
{
    if (g_read_index == g_write_index) {
        return 0;
    }

    *byte = g_rx_buffer[g_read_index];
    g_read_index = (g_read_index + 1) % RX_BUFFER_SIZE;
    return 1;
}
```

这个例子包含了数组、取模、`static`、`volatile`、中断和缓冲区边界，是嵌入式 C 的典型组合。

## 6. 常见错误

- 把中断里修改的变量写成普通变量，导致主循环读不到变化。
- 缓冲区没有边界检查，收到长帧后数组越界。
- 用全局变量到处传数据，模块之间耦合严重。
- 用 `delay` 等待串口接收，导致系统响应变慢。
- 只会写功能，不会保存错误码和调试信息。

## 7. 调试方法

- 串口打印关键变量，但不要在高频中断里大量打印。
- 用断点观察缓冲区读写指针是否正确变化。
- 用逻辑分析仪确认串口实际波形和波特率。
- 对协议帧使用十六进制日志，不要只打印字符串。
- 对数组访问增加长度判断，先防止越界。

## 8. 面试常问问题

1. `static` 修饰全局变量和局部变量有什么区别？
2. `volatile` 在嵌入式中常用于哪些场景？
3. 中断函数里为什么不建议做复杂协议解析？
4. 环形缓冲区如何判断空和满？
5. 结构体在协议解析中有什么用途？

## 9. 简历表达方式

可以写：

> 使用嵌入式 C 实现串口接收缓冲区和 Modbus RTU 帧解析，完成地址、功能码、长度和 CRC16 校验，并通过串口日志定位异常帧和超时问题。

这比“熟悉 C 语言”更具体，也更容易引出项目追问。

## 10. 小练习

1. 写一个 64 字节环形缓冲区。
2. 写一个函数，把两个字节合成一个 16 位寄存器值。
3. 用结构体描述设备的 4 个参数。
4. 写一个状态机，识别帧头 `0xAA 0x55`。
5. 思考哪些变量需要 `volatile`。

## 11. 小结

嵌入式 C 的重点不是语法炫技，而是工程可靠性。你要能解释变量作用域、内存边界、中断共享、协议字节和调试方法。

把 C 语言学到能服务串口、RS485、Modbus、FreeRTOS 和 Qt 联调，才是真正贴近岗位的学习方式。
