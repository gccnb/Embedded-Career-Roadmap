# Qt Modbus Demo 测试用例

这些用例只用于学习和自测，不代表任何真实设备的寄存器表。真实设备的寄存器地址、功能码支持范围、字节含义和异常码解释，必须以设备手册、协议文档或实测结果为准。

## 1. 03 功能码请求帧

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| 从机地址 | `01` | 示例从机地址 |
| 功能码 | `03` | 读保持寄存器 |
| 起始地址 | `00 00` | 教学示例地址，不对应真实设备 |
| 寄存器数量 | `00 02` | 读取 2 个寄存器 |
| CRC | `C4 0B` | Modbus RTU 低字节在前 |

完整请求帧：

```text
01 03 00 00 00 02 C4 0B
```

## 2. 06 功能码请求帧

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| 从机地址 | `01` | 示例从机地址 |
| 功能码 | `06` | 写单个保持寄存器 |
| 寄存器地址 | `00 01` | 教学示例地址，不对应真实设备 |
| 写入值 | `00 05` | 教学示例数值 |
| CRC | `18 09` | Modbus RTU 低字节在前 |

完整请求帧：

```text
01 06 00 01 00 05 18 09
```

## 3. 推荐测试步骤

1. 先不接真实设备，只运行程序，确认界面能启动。
2. 使用虚拟串口或串口环回，确认 TX 日志能显示完整请求帧。
3. 配合 `03_RS485_Modbus/codes/modbus_rtu_demo.c` 的模拟思路，编写或运行一个模拟从机。
4. 发送 03 请求，检查 RX 日志是否显示原始响应帧，CRC 错误时是否提示。
5. 发送 06 请求，检查响应是否回显地址和值。
6. 故意改错 CRC、少发一个字节、改错波特率，观察日志如何帮助定位。
7. 在模拟 RX 输入框填写 `01 03 04 00 19 00 64 2A 1F`，点击“模拟 RX”，检查解析表格是否出现 03 响应记录。
8. 输入错误 CRC 帧，例如 `01 03 04 00 19 00 64 00 00`，检查是否提示 CRC 校验失败。
9. 点击“导出日志”，检查 CSV 是否包含 `time`、`direction`、`message` 三列。

## 4. 面试复盘提示

回答 Qt 上位机项目时，不要只说“我做了界面”。建议按下面顺序讲：

1. 为什么需要上位机：用于串口参数配置、协议帧发送、响应解析和日志保存。
2. 模块怎么拆：UI、串口管理、Modbus 组帧、CRC、日志显示。
3. 怎么验证：用 03/06 请求帧、模拟 RX 输入、模拟从机、错误 CRC、超时、解析表格、CSV 导出和日志复盘。
4. 边界是什么：示例只用于学习，真实设备必须依据协议手册和实测结果。
