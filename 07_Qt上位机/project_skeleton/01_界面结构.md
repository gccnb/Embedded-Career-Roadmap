# Qt 上位机界面结构

## 1. 界面目标

这个界面服务于一个明确目标：调试 RS485/Modbus 通信链路。界面不追求复杂，先保证串口参数能配置、请求帧能发送、响应帧能显示、日志能导出。

## 2. 推荐分区

| 区域 | 控件类型 | 作用 |
|---|---|---|
| 串口配置区 | 下拉框、按钮 | 选择端口号、波特率、校验位并打开串口 |
| 功能码操作区 | 输入框、按钮 | 发送 03 读寄存器和 06 写寄存器 |
| 寄存器显示区 | 表格 | 显示地址、原始值、解析值、更新时间 |
| 日志区 | 文本框或表格 | 显示 TX/RX 原始十六进制帧 |
| 状态栏 | 标签 | 显示串口状态、超时、CRC 错误等 |

## 3. 推荐布局

```text
┌──────────────────────────────────────────────┐
│ 串口配置：COM  波特率  校验位  打开/关闭       │
├──────────────────────────────────────────────┤
│ 03 读保持寄存器：从机地址 起始地址 数量 发送   │
│ 06 写单个寄存器：从机地址 寄存器地址 值 发送   │
├──────────────────────┬───────────────────────┤
│ 寄存器表             │ TX/RX 日志             │
│ 地址 原始值 解析值    │ 时间 方向 原始帧 结果   │
└──────────────────────┴───────────────────────┘
```

## 4. 交互流程

1. 用户选择串口参数并点击打开。
2. 程序打开串口，状态栏显示已连接。
3. 用户输入从机地址、寄存器地址和数量。
4. 程序生成 Modbus 请求帧，显示 TX 日志。
5. 收到响应后校验 CRC，显示 RX 日志。
6. 解析成功后更新寄存器表，失败则显示错误原因。

## 5. 常见错误

- UI 线程中阻塞等待串口响应，导致界面卡死。
- 只显示解析值，不显示原始 TX/RX 帧。
- 没有超时提示，用户不知道是没响应还是程序卡住。
- 输入框没有范围检查，非法地址和数量直接进入组帧。
- 日志无法导出，面试和复盘缺少证据。

## 6. 调试建议

先用串口助手或模拟从机验证请求帧，再接入真实 RS485 链路。涉及真实设备、端子、A/B 标识、供电和接地时，必须查设备手册、原理图和实测结果。
