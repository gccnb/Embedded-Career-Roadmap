# Qt 上位机总览

## 1. 本节要解决什么问题

本节要解决的问题是：理解 Qt 如何做串口配置、协议调试、日志显示和参数下发。它更接近项目收尾和求职表达阶段：不仅要能写代码，还要能把调试过程、模块边界和项目价值讲清楚。

对初学者来说，不要把上位机、项目实战或面试准备看成最后临时补的东西。它们应该从学习早期就开始积累：每写一个功能，就留下日志；每解决一个问题，就写复盘；每完成一个模块，就尝试改写成简历表达。

## 2. 基本概念

Qt 上位机总览 可以理解为把底层知识组织起来的方法。单片机负责采集和控制，RS485/Modbus 负责通信，FreeRTOS 负责任务拆分，Qt 或面试文档负责展示和表达。

概念学习不要停留在“知道名词”。你要能说明它和项目中哪些模块有关，输入输出是什么，失败时如何定位。

## 3. 工程用途

Qt 上位机负责把下位机调试过程可视化：串口参数、发送帧、接收帧、日志、按钮和表格都可以放在一个工具里。它不是替代单片机，而是帮助你把 RS485/Modbus 项目调通、记录和展示。

本模块新增了 `project_skeleton` 目录，用于说明一个 Qt Modbus 调试上位机的推荐骨架：

| 文档 | 作用 |
|---|---|
| `project_skeleton/README.md` | 说明推荐目录结构和最小功能闭环 |
| `project_skeleton/01_界面结构.md` | 说明串口配置、功能码操作、寄存器表和日志区 |
| `project_skeleton/02_模块划分.md` | 说明串口管理、Modbus 组帧、响应解析、日志管理的边界 |
| `project_skeleton/03_日志导出格式.md` | 说明 CSV 日志字段和 TX/RX 记录格式 |

本模块还新增了 `qt_modbus_debugger_demo` 目录，提供一个教学用 Qt 最小 Demo。它包含 CMake 工程、串口打开关闭、Modbus 03/06 请求帧生成、模拟 RX 输入、CRC16 校验、解析结果表格、TX/RX 日志显示和 CSV 日志导出。这个 Demo 不绑定任何真实设备寄存器，只用于帮助你理解上位机项目的模块组织方式。

如果你做的是个人学习项目，要明确写“个人项目”或“课程外实践”。公开资料库中只能使用抽象工业控制、机器视觉控制、串口调试等场景，不得泄露真实公司、客户、产线和设备内部资料。

## 4. 简单代码或伪代码

下面示例只表达流程，不代表真实项目协议，也不绑定具体公司或设备。

```cpp
connect(button, &QPushButton::clicked, this, [this]() {
    QByteArray frame = QByteArray::fromHex("01 03 00 00 00 02");
    serial.write(frame);
});
```

阅读这段示例时，重点不是语法，而是看清楚每一步留下了什么证据：输入、处理、输出、日志和复盘。

## 5. 常见错误

- 在界面线程里做耗时串口操作，导致窗口卡死。
- 只显示解析后的值，不保存原始十六进制帧。
- 日志没有时间戳，后续无法分析超时。
- 把 UI 做得很复杂，但核心通信功能不稳定。
- 简历表达过于空泛，面试官追问时没有细节支撑。

这些错误都可以通过“保留原始日志、写清楚调试步骤、只写自己能解释的内容”来避免。

## 6. 调试方法

调试时建议把过程写成表格：时间、现象、输入、输出、怀疑点、验证方法、结论。Qt 上位机要保存 TX/RX 原始帧；项目实战要保存接线依据、协议说明和测试步骤；面试准备要把问题复盘成 1 分钟回答。

涉及控制卡、驱动器、传感器、端子定义或接线时，必须以数据手册、原理图和实测结果为准，不能凭经验编造。

## 7. 面试常问问题

1. 问：Qt 上位机总览 能体现什么工程能力？
   答：它体现把底层代码、通信协议、调试过程和项目表达串起来的能力，不只是会写一个函数。
2. 问：如果面试官追问细节，你怎么回答？
   答：按“需求、实现、调试、问题、改进”回答，并拿出自己能解释的日志或代码片段。
3. 问：如何避免项目描述夸大？
   答：只写自己完成和验证过的内容，学习项目就写学习项目，不写真实公司交付和客户信息。

## 8. 简历表达方式

这句话后续可以继续细化为具体项目职责，例如“完成 Qt 串口日志保存”“完成 Modbus 03/06 请求帧生成”“完成 CRC 校验和 TX/RX 日志复盘”。
