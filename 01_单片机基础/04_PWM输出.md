# PWM 输出

## 1. 本节要解决什么问题

本节先解决一个很实际的问题：理解占空比、频率和电机、蜂鸣器、背光等控制方式。对初学者来说，不要一开始就追求把所有细节背下来，而是先弄清楚它在项目链路里处在哪一层、输入是什么、输出是什么、出错时怎么查。

如果你后面要做 RS485、Modbus RTU、FreeRTOS 多任务或 Qt 上位机项目，PWM 输出 会成为其中一个基础环节。学这一节的目标，是让你能写出最小示例，能解释工程用途，也能在面试中讲清楚自己做过什么。

## 2. 基本概念

PWM 输出 可以先从三个角度理解：第一，它是什么；第二，它在嵌入式项目中连接哪些模块；第三，它出问题时会表现成什么现象。概念不是为了背，而是为了帮助你判断程序在哪里出了问题。

学习时建议把概念落到变量、函数、流程和调试记录上。比如通信相关内容要看原始字节，任务相关内容要看任务状态，外设相关内容要看输入输出电平和时序。

## 3. 工程用途

在单片机项目里，它通常和 GPIO、USART、定时器、中断、PWM、RS485 方向控制一起出现。学会它不是为了背寄存器名，而是为了能把一个输入、一个输出、一个通信事件稳定地接到程序里。涉及真实引脚、电源、端子和传感器时，必须以数据手册、原理图和实测结果为准，不能凭经验编造。

在求职项目里，你可以把这一节和“下位机通信控制器 + Qt 上位机调试工具”连接起来。下位机负责采集、控制和协议响应，上位机负责发送命令、显示日志和保存调试过程。这样学到的不是孤立知识，而是一条能写进简历的工程主线。

## 4. 简单代码或伪代码

下面的示例只展示思路，不绑定具体芯片库或真实设备协议。真实项目要根据芯片 HAL、BSP 或 FreeRTOS 配置调整。

```c
void app_loop(void)
{
    read_input();
    update_state_machine();
    process_uart_frame();
    refresh_output();
}
```

代码阅读时先看数据从哪里来，再看中间状态如何变化，最后看输出给谁。初学阶段不需要追求复杂封装，先保证流程能解释、边界能检查、日志能保存。

## 5. 常见错误

- 只背外设定义，不知道项目里为什么用。
- 涉及接线时凭经验猜 TX/RX、A/B 或电源正负。
- 在中断里做太多事情，导致主循环响应变慢。
- 写代码时没有边界检查，调试时只看现象不看数据。
- 简历只堆关键词，面试时讲不出自己的实现。

这些错误的共同点是：代码看起来能跑，但没有形成可验证闭环。工程里不能只说“应该没问题”，要能拿出日志、波形、返回值或测试步骤。

## 6. 调试方法

调试时先把问题分层：硬件连接、外设参数、代码流程、日志记录。单片机基础问题可以先用 LED、串口打印、断点、逻辑分析仪确认输入输出；FreeRTOS 问题要观察任务心跳、队列长度、栈剩余和超时次数。

建议每次调试都记录四项：输入是什么、期望输出是什么、实际输出是什么、下一步验证什么。这样后续写项目复盘和面试回答时，就不会只剩一句“后来我调好了”。

## 7. 面试常问问题

1. 问：PWM 输出 在项目里主要解决什么问题？
   答：它不是孤立知识点，而是服务输入输出、通信、任务拆分或调试表达。回答时要结合自己写过的代码和遇到的问题。
2. 问：初学者最容易在哪里出错？
   答：常见错误是只背概念、不看边界条件、不保存调试数据。工程里要能说清楚输入、输出、异常和验证方式。
3. 问：如果这个模块出问题，你怎么排查？
   答：先复现，再分层检查硬件、参数、代码逻辑和日志。涉及硬件时回到手册、原理图和实测结果。

## 8. 简历表达方式

可以写成这样：

> 在个人嵌入式通信实践中，围绕 PWM 输出 完成基础功能实现、调试日志记录和问题复盘，并将其接入 RS485/Modbus、FreeRTOS 或 Qt 上位机学习链路。

如果你确实写了代码，可以把“完成基础功能实现”换成更具体的模块名，例如“完成串口接收缓冲区”“完成任务队列传递”。不要写无法公开或无法证明的真实公司信息。

## 10. 小结

PWM 输出 的基础版学习目标不是一次性掌握所有细节，而是建立工程直觉：知道它解决什么问题，知道最小代码怎么写，知道常见错误怎么查，知道面试和简历该怎么表达。下一轮精修时，可以继续补充更完整的代码、实验步骤和调试案例。
