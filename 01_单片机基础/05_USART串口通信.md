# USART 串口通信

## 1. 本节要解决什么问题

USART 是很多嵌入式项目的第一条通信链路。你后面学 RS485、Modbus RTU、串口日志、Qt 上位机，底层都离不开“单片机如何按字节收发数据”。

本节要解决的问题是：串口参数是什么，单片机如何发送和接收字节，为什么不能只会 `printf`，以及串口问题应该怎么调。

## 2. 基本概念

USART 可以理解成单片机内部的串行通信外设。它负责把一个字节按位发出去，也负责把外部来的电平变化重新组合成字节。

常见参数包括：

| 参数 | 含义 | 常见值 |
| --- | --- | --- |
| 波特率 | 每秒传输多少位 | 9600、115200 |
| 数据位 | 一个数据字包含几位 | 8 位常见 |
| 校验位 | 用于简单错误检查 | 无校验、偶校验、奇校验 |
| 停止位 | 一帧字节结束标志 | 1 位常见 |
| 收发方式 | 查询、中断、DMA | 入门先学查询和中断 |

USART 只是 MCU 外设。TTL 串口、RS232、RS485 是外部电气接口；Modbus RTU、自定义帧才是通信协议。

## 3. 工程用途

串口在项目中常做三件事：

- 调试日志：输出当前状态、错误码、接收帧；
- 设备通信：和传感器、控制板、上位机交换数据；
- 协议承载：作为 RS485/Modbus RTU 的字节收发入口。

在工程里，串口最重要的不是“能发字符串”，而是能稳定接收、能保存原始字节、能处理超时和异常。涉及真实接口接线时，TX/RX、GND、电平、RS485 A/B、端子定义都必须以数据手册、原理图和实测结果为准，不能凭经验猜。

## 4. 简单代码或伪代码

下面是一个入门级串口接收思路：中断里只收字节，主循环处理完整帧。

```c
#define RX_SIZE 64

static unsigned char rxBuffer[RX_SIZE];
static volatile unsigned char rxIndex = 0;
static volatile unsigned char rxFlag = 0;

void USART_RX_IRQHandler(void)
{
    unsigned char byte = uart_read_byte();

    if (rxFlag != 0) {
        return;
    }

    if (byte == '#') {
        rxBuffer[rxIndex] = 0;
        rxFlag = 1;
    } else if (rxIndex < RX_SIZE - 1) {
        rxBuffer[rxIndex++] = byte;
    } else {
        rxIndex = 0;
    }
}

void app_loop(void)
{
    if (rxFlag != 0) {
        parse_command(rxBuffer);
        rxIndex = 0;
        rxFlag = 0;
    }
}
```

这个例子适合自定义文本协议。进入 Modbus RTU 后，不能再用 `#` 做帧尾，因为 Modbus 是二进制协议，要用长度、超时和 CRC 判断完整帧。

## 5. 常见错误

- 波特率、校验位、停止位两端不一致。
- TX/RX 没交叉，或者忘记共地。
- 中断里做复杂解析和大量打印，导致丢字节。
- 接收缓冲区没有长度判断，数组越界。
- 只打印字符串，不保存十六进制原始帧。
- 把 USART、RS485、Modbus 三个层次混在一起。

这些错误的共同特点是：表面看像“通信不通”，实际可能是参数、电气、时序、协议或代码边界任意一层出了问题。

## 6. 调试方法

建议按顺序排查：

1. 用示波器或逻辑分析仪确认 TX 引脚确实有波形。
2. 用串口助手确认波特率、数据位、校验位、停止位一致。
3. 先发送固定字节，例如 `55 AA`，再看接收端是否一致。
4. 打印或保存十六进制日志，不要只看字符串。
5. 如果用 RS485，继续检查方向控制、A/B 线、终端电阻和接收使能。

调试记录要写清楚：发送了什么、收到什么、参数是什么、错误现象是什么、下一步验证什么。面试时这些记录比一句“我调通过串口”更有说服力。

## 7. 面试常问问题

1. 问：USART 和 UART 有什么区别？
   答：UART 是异步串口，USART 既可支持同步也可支持异步。嵌入式项目里常用的是异步串口模式。

2. 问：串口通信必须配置哪些参数？
   答：至少要保证波特率、数据位、校验位、停止位一致，否则会出现乱码、丢字节或完全收不到。

3. 问：为什么串口接收常用中断？
   答：因为数据随时可能到来，主循环死等会阻塞其他任务。中断可以快速保存字节，再由主循环或任务解析。

4. 问：串口中断里适合做什么？
   答：适合读数据寄存器、放入缓冲区、更新标志位。不适合做复杂协议解析、长时间打印或等待。

5. 问：USART 和 RS485、Modbus 的关系是什么？
   答：USART 负责字节收发，RS485 负责总线电气传输，Modbus RTU 规定这些字节的协议含义。

## 8. 简历表达方式

> 使用 USART 接收中断实现串口数据缓存和完整帧处理，完成自定义协议命令解析，并为后续 RS485/Modbus RTU 通信模块提供字节收发基础。

如果项目中做了日志，可以补一句“保存 TX/RX 十六进制日志用于定位乱码、丢字节和 CRC 错误”。

## 9. 小练习

1. 写一个串口发送字符串函数，再写一个发送十六进制数组函数。
2. 用 `#` 做帧尾，实现 `LED,1#` 这类命令接收。
3. 故意把波特率配错，观察乱码现象。
4. 把接收帧打印成十六进制格式。
5. 说明 USART、RS485、Modbus RTU 三者分别解决什么问题。

## 10. 小结

USART 是嵌入式通信的入口。你要先掌握参数配置、字节收发、中断接收、缓冲区和日志，再去学 RS485 和 Modbus。

面试时不要只说“我会串口”，要能讲清楚：串口参数怎么配、接收为什么用中断、缓冲区如何防溢出、乱码和丢字节怎么排查。
