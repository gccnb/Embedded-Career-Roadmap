# 状态机类设计

## 1. 本节要解决什么问题

本节要解决的问题是：如何用 C++ 类组织设备或流程状态，让系统行为可控、可调试。

嵌入式项目里，状态机非常常见。串口协议解析是状态机，设备运行流程是状态机，机器视觉控制流程也是状态机。初学者常见写法是在 `while (1)` 里堆很多 `if else`，短期能跑，后期很难维护。

C++ 状态机类的价值是把状态、事件、转移条件和动作集中管理。

## 2. 基本概念

状态机由四个核心概念组成：

| 概念 | 含义 | 示例 |
|---|---|---|
| 状态 | 系统当前处于什么阶段 | 空闲、运行、完成、报警 |
| 事件 | 触发状态变化的输入 | 启动命令、完成信号、超时 |
| 转移 | 从一个状态切换到另一个状态 | 空闲 -> 运行 |
| 动作 | 状态变化时执行的操作 | 清计数、发命令、记录日志 |

状态机类通常提供 `handleEvent()` 或 `tick()` 接口。外部把事件传进来，状态机内部决定是否切换状态。

## 3. 工程用途

状态机适合处理有明确流程的项目：

- RS485 协议解析：等待帧头、等待长度、等待数据、等待校验；
- Modbus 轮询任务：空闲、发送请求、等待响应、处理响应、超时；
- 机器控制流程：空闲、启动、运行、完成、报警；
- Qt 上位机：未连接、已连接、发送中、等待响应、错误。

状态机能避免逻辑分散。面试时如果能画出状态图并说明每个事件的来源，会比只说“我用 if 判断状态”更清楚。

## 4. 简单代码或伪代码

下面示例演示一个抽象机器流程状态机。

```cpp
#include <stdint.h>

class MachineStateMachine {
public:
    enum State {
        STATE_IDLE = 0,
        STATE_STARTING,
        STATE_RUNNING,
        STATE_DONE,
        STATE_ALARM
    };

    enum Event {
        EVENT_START = 0,
        EVENT_STARTED,
        EVENT_FINISH,
        EVENT_ERROR,
        EVENT_RESET
    };

    MachineStateMachine()
        : state(STATE_IDLE), lastEvent(EVENT_RESET)
    {
    }

    void handleEvent(Event event)
    {
        lastEvent = event;

        switch (state) {
        case STATE_IDLE:
            if (event == EVENT_START) {
                state = STATE_STARTING;
            }
            break;

        case STATE_STARTING:
            if (event == EVENT_STARTED) {
                state = STATE_RUNNING;
            } else if (event == EVENT_ERROR) {
                state = STATE_ALARM;
            }
            break;

        case STATE_RUNNING:
            if (event == EVENT_FINISH) {
                state = STATE_DONE;
            } else if (event == EVENT_ERROR) {
                state = STATE_ALARM;
            }
            break;

        case STATE_DONE:
        case STATE_ALARM:
            if (event == EVENT_RESET) {
                state = STATE_IDLE;
            }
            break;
        }
    }

    State currentState() const
    {
        return state;
    }

private:
    State state;
    Event lastEvent;
};
```

这段代码只表达状态转移，不绑定真实机器。真实设备的启动条件、完成条件、报警条件必须根据项目需求、设备手册和实测结果确定。

## 5. 常见错误

- 状态没有枚举，直接用数字 `0`、`1`、`2`，后续难读。
- 状态转移分散在多个文件里，难以确认系统到底怎么运行。
- 没有错误状态，异常只能靠返回值临时处理。
- 没有复位事件，报警后无法回到空闲。
- 状态机里直接做耗时操作，影响实时性。
- 状态机没有日志，现场问题无法复盘。

## 6. 调试方法

调试状态机时，重点看“事件输入”和“状态输出”。

| 当前状态 | 输入事件 | 期望新状态 |
|---|---|---|
| `STATE_IDLE` | `EVENT_START` | `STATE_STARTING` |
| `STATE_STARTING` | `EVENT_STARTED` | `STATE_RUNNING` |
| `STATE_RUNNING` | `EVENT_FINISH` | `STATE_DONE` |
| 任意运行状态 | `EVENT_ERROR` | `STATE_ALARM` |
| `STATE_ALARM` | `EVENT_RESET` | `STATE_IDLE` |

建议日志格式：

```text
state=IDLE event=START next=STARTING
state=RUNNING event=ERROR next=ALARM
```

如果系统状态异常，先查事件是否真的触发，再查状态转移表是否允许这个转移，最后查状态进入后的动作。

## 7. 面试常问问题

1. 问：为什么嵌入式项目常用状态机？
   答：因为很多流程有明确阶段和事件，状态机能让状态转移可控、可读、可调试。

2. 问：状态机和一堆 if else 有什么区别？
   答：状态机明确列出状态、事件和转移关系，逻辑集中；散乱 if else 容易出现遗漏和冲突。

3. 问：状态机里适合做耗时操作吗？
   答：不适合。状态机应尽量快速处理事件，耗时操作可以交给任务或驱动层。

4. 问：状态机如何和 FreeRTOS 配合？
   答：任务从队列接收事件，调用状态机处理，再根据状态决定控制动作或日志输出。

5. 问：状态机如何用于 Modbus 项目？
   答：可用于协议解析，也可用于主站轮询流程，比如发送请求、等待响应、处理成功、处理超时。

## 10. 小结

状态机类设计是嵌入式 C++ 很实用的一部分。它把状态、事件和转移集中管理，让项目行为更清楚。对求职项目来说，状态机能把通信、控制和日志串起来，是从“能写代码”走向“能设计模块”的关键一步。
