# 设备类设计

## 1. 本节要解决什么问题

本节要解决的问题是：如何用 C++ 类描述一个外部设备或功能模块，让项目代码更容易组织。

在嵌入式项目里，“设备”可以是一个传感器、一个 RS485 从机、一个执行模块、一个模拟控制对象，也可以是 Qt 上位机里的一个远程设备模型。C 语言通常用结构体和函数组合实现；C++ 可以把状态和操作封装成设备类。

设备类不是为了复杂，而是为了让接口明确：初始化、读取状态、写参数、处理响应、保存错误。

## 2. 基本概念

一个设备类通常包含以下内容：

| 内容 | 示例 | 作用 |
|---|---|---|
| 设备地址 | `address` | 区分 RS485/Modbus 总线上的节点 |
| 当前状态 | `state` | 表示离线、空闲、运行、报警 |
| 错误码 | `lastError` | 记录最近一次失败原因 |
| 操作接口 | `readStatus()`、`writeParam()` | 对外提供清晰动作 |
| 响应处理 | `onResponse()` | 根据协议响应更新状态 |

设备类应表达“这个设备能做什么”，而不是把所有协议细节都塞进去。协议组帧和解析可以交给协议类，设备类负责调用协议类并维护设备状态。

## 3. 工程用途

设备类适合管理多个相似设备。比如 RS485 总线上有多个模拟从机，每个设备都有地址、在线状态、最后通信时间、当前报警状态。如果没有设备类，代码很容易变成多个全局数组和一堆散函数。

典型分层：

```text
Device 类：管理设备地址、状态、错误
Protocol 类：负责组帧和解析
Port 类：负责串口或 RS485 字节收发
```

这种分层也适合 Qt 上位机。界面显示设备状态，底层串口发送请求，中间设备类维护状态，日志模块记录变化。

## 4. 简单代码或伪代码

下面示例演示一个简化的 Modbus 设备类。

```cpp
#include <stdint.h>

class ModbusDevice {
public:
    enum State {
        STATE_OFFLINE = 0,
        STATE_IDLE,
        STATE_RUNNING,
        STATE_ALARM
    };

    explicit ModbusDevice(uint8_t addr)
        : address(addr), state(STATE_OFFLINE), lastError(0), statusWord(0)
    {
    }

    uint8_t getAddress() const
    {
        return address;
    }

    State getState() const
    {
        return state;
    }

    uint16_t getStatusWord() const
    {
        return statusWord;
    }

    void markOffline()
    {
        state = STATE_OFFLINE;
        lastError = 1;
    }

    void updateStatus(uint16_t word)
    {
        statusWord = word;

        if (word & 0x0002u) {
            state = STATE_ALARM;
        } else if (word & 0x0001u) {
            state = STATE_RUNNING;
        } else {
            state = STATE_IDLE;
        }
    }

    uint8_t error() const
    {
        return lastError;
    }

private:
    uint8_t address;
    State state;
    uint8_t lastError;
    uint16_t statusWord;
};
```

这里的状态位只是教学示例，不代表真实设备协议。真实设备状态位必须以协议文档、数据手册和实测结果为准。

## 5. 常见错误

- 设备类职责过大，既做串口收发，又做协议解析，又做业务控制。
- 类名叫设备类，但内部全是 UI 显示逻辑，无法复用到下位机。
- 没有错误状态，通信失败后上层不知道设备是否离线。
- 没有保存原始状态字，只保存解析后的枚举。
- 把真实设备地址、状态位、寄存器表写进公开示例。

## 6. 调试方法

设备类调试重点是状态变化是否正确。

| 测试输入 | 期望设备状态 |
|---|---|
| 初始化后 | `STATE_OFFLINE` |
| 收到状态字 `0x0000` | `STATE_IDLE` |
| 收到状态字 `0x0001` | `STATE_RUNNING` |
| 收到状态字 `0x0002` | `STATE_ALARM` |
| 通信超时 | `STATE_OFFLINE`，错误码更新 |

建议在日志里记录：

```text
device=1 rawStatus=0x0001 oldState=IDLE newState=RUNNING
```

如果状态不对，先查原始响应帧，再查状态字高低字节，再查位定义，最后查设备类更新逻辑。

## 7. 面试常问问题

1. 问：设备类和协议类有什么区别？
   答：协议类负责组帧和解析字节；设备类负责维护设备地址、状态、错误和对外操作接口。

2. 问：为什么设备类要保存错误码？
   答：通信超时、CRC 错误、异常响应等都需要被上层看到，错误码便于日志和问题定位。

3. 问：设备类是否应该直接访问硬件寄存器？
   答：一般不建议。底层硬件访问放在驱动层，设备类通过接口调用，边界更清楚。

4. 问：如何管理多个 RS485 设备？
   答：可以创建多个设备对象，每个对象保存地址和状态，由调度器周期轮询或按需访问。

5. 问：为什么要保存原始状态字？
   答：解析出错时需要回到原始数据定位问题，不能只保留转换后的状态枚举。

## 10. 小结

设备类设计的核心是抽象边界。它把设备地址、状态、错误和操作接口集中起来，让项目更容易扩展和调试。对求职来说，设备类能体现你不仅会写协议函数，还能把通信对象组织成可维护的工程结构。
