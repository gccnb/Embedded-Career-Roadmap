# Qt 工业串口调试上位机

## 1. 本节要解决什么问题

本节要解决的问题是：用 Qt 做串口配置、报文发送、日志保存和参数表。它更接近项目收尾和求职表达阶段：不仅要能写代码，还要能把调试过程、模块边界和项目价值讲清楚。

对初学者来说，不要把上位机、项目实战或面试准备看成最后临时补的东西。它们应该从学习早期就开始积累：每写一个功能，就留下日志；每解决一个问题，就写复盘；每完成一个模块，就尝试改写成简历表达。

## 2. 基本概念

Qt 工业串口调试上位机 可以理解为把底层知识组织起来的方法。单片机负责采集和控制，RS485/Modbus 负责通信，FreeRTOS 负责任务拆分，Qt 或面试文档负责展示和表达。

概念学习不要停留在“知道名词”。你要能说明它和项目中哪些模块有关，输入输出是什么，失败时如何定位。

## 3. 工程用途

项目实战的重点不是编造“大项目”，而是把公开可复现的学习内容做成闭环：需求、协议、代码、调试、问题、复盘、简历表达。不要写真实公司、客户或产线信息。涉及接线、控制卡、驱动器、传感器时必须查数据手册、原理图和实测结果。

如果你做的是个人学习项目，要明确写“个人项目”或“课程外实践”。公开资料库中只能使用抽象工业控制、机器视觉控制、串口调试等场景，不得泄露真实公司、客户、产线和设备内部资料。

## 5. 常见错误

- 项目目标太大，最后没有一个能演示的闭环。
- 写了真实公司或设备细节，违反公开资料边界。
- 只讲最终效果，不记录调试过程。
- 没有把项目拆成模块，面试时讲不清职责。
- 简历表达过于空泛，面试官追问时没有细节支撑。

这些错误都可以通过“保留原始日志、写清楚调试步骤、只写自己能解释的内容”来避免。

## 6. 调试方法

调试时建议把过程写成表格：时间、现象、输入、输出、怀疑点、验证方法、结论。Qt 上位机要保存 TX/RX 原始帧；项目实战要保存接线依据、协议说明和测试步骤；面试准备要把问题复盘成 1 分钟回答。

涉及控制卡、驱动器、传感器、端子定义或接线时，必须以数据手册、原理图和实测结果为准，不能凭经验编造。

## 7. 面试常问问题

1. 问：Qt 工业串口调试上位机 能体现什么工程能力？
   答：它体现把底层代码、通信协议、调试过程和项目表达串起来的能力，不只是会写一个函数。
2. 问：如果面试官追问细节，你怎么回答？
   答：按“需求、实现、调试、问题、改进”回答，并拿出自己能解释的日志或代码片段。
3. 问：如何避免项目描述夸大？
   答：只写自己完成和验证过的内容，学习项目就写学习项目，不写真实公司交付和客户信息。

## 项目展示化补充

### 项目结构

```text
qt_serial_debugger/
├── main.cpp            Qt 程序入口
├── mainwindow.ui       串口配置、按钮、日志区和表格
├── mainwindow.cpp      界面逻辑和信号槽
├── serial_worker.cpp   串口收发封装
├── protocol_parser.cpp 自定义协议或 Modbus 解析
└── logs/               调试日志导出目录
```

### 运行流程

```text
选择串口参数
-> 打开串口
-> 点击读取或写入按钮
-> 生成请求帧并显示 TX
-> readyRead 接收字节并缓存
-> 校验完整帧并显示 RX
-> 更新表格或错误提示
```

如果接入真实 RS485 设备，串口参数、A/B 端子、供电、接地和隔离方式必须查设备手册、模块手册、原理图，并通过实测确认。上位机日志不能替代硬件核验。

### 测试用例

| 测试项 | 操作 | 期望结果 |
|---|---|---|
| 打开串口 | 选择有效串口并打开 | 状态栏显示已连接 |
| 发送 03 请求 | 点击读取按钮 | TX 日志显示完整请求帧 |
| 接收正确响应 | 模拟从机返回正常帧 | 表格更新寄存器值 |
| CRC 错误 | 返回错误 CRC | UI 显示 CRC 错误并保存原始 RX |
| 超时 | 从机不返回 | 500 ms 后提示超时 |

### 调试日志样例

```text
[14:18:09.301] OPEN COM5 9600 8N1
[14:18:12.008] TX 01 03 00 00 00 02 C4 0B
[14:18:12.026] RX 01 03 04 00 64 00 C8 BA 7A
[14:18:12.027] UI update row=0 value=100 row=1 value=200
```

面试时可以围绕这条日志讲清楚 Qt 信号槽、QSerialPort、超时定时器和协议解析的分工。
