# Linux 目录结构

## 1. 本节要解决什么问题

本节要解决的问题是：理解 /dev、/proc、/sys、/etc、/var/log 在调试中的作用。很多同学学到这里时，会觉得概念突然变多，但真正重要的是把它放回工程场景：它接收什么输入，产生什么输出，和 RS485、Modbus、FreeRTOS 或 Qt 上位机有什么关系。

学习本节时，不要求一次写出完整项目，而是先能读懂基础代码，能解释为什么这样写，能知道出问题时先查哪里。

## 2. 基本概念

Linux 目录结构 不是孤立名词。它背后对应一种组织程序的方法：让代码边界更清楚，让调试信息更容易保存，让模块之间的关系更容易描述。

对于初学者，概念可以先抓三点：它管理什么资源，它和谁通信，它失败时会返回什么现象。只要能围绕这三点讲清楚，就比单纯背定义更接近工程面试。

## 3. 工程用途

嵌入式 Linux 更像是在操作系统上写应用程序。串口、GPIO、网络、文件和进程都有系统接口。它常用于网关、上位机边缘设备、工业控制主机和视觉控制系统，不再像裸机那样直接操作每一个寄存器。涉及真实硬件接口时仍要以数据手册、原理图和实测结果为准。

在学习项目中，可以把它接到“RS485/Modbus 下位机 + Qt 上位机”主线上：底层负责通信或系统接口，中间层负责协议解析，应用层负责日志和参数。这样简历中就不是孤立写“学过 Linux 目录结构”，而是能讲出具体模块。

## 4. 简单代码或伪代码

下面代码只展示入门思路，不绑定真实公司项目，也不代表任何真实设备协议。实际项目要根据编译器、系统库、板级支持包和设备手册调整。

```c
int fd = open("/dev/ttyS1", O_RDWR);
if (fd < 0) {
    return -1;
}

write(fd, tx_buf, tx_len);
read(fd, rx_buf, sizeof(rx_buf));
close(fd);
```

看代码时注意三件事：接口是否清楚，错误是否能返回，调试时能不能观察输入和输出。

## 5. 常见错误

- 把 Linux 当成大号单片机，不理解文件描述符、进程和权限。
- 串口参数没有配置正确就开始怀疑协议。
- 只会敲命令，不知道命令输出代表什么。
- 多线程读写共享数据却没有同步。
- 简历写“熟悉”，但面试时说不出自己在哪个项目中用过。

这些错误的根源通常不是没背定义，而是没有把知识点放到工程链路里验证。

## 6. 调试方法

调试时先确认最小可运行路径：输入是否到达、函数是否被调用、返回值是否正确、日志是否保存。C++ 相关内容要检查对象初始化和接口调用顺序；Linux 相关内容要检查设备节点、权限、返回值、进程状态和系统日志。

如果涉及 GPIO、串口、传感器、控制卡或驱动器，硬件连接必须以数据手册、原理图和实测结果为准，不要凭经验猜。

## 7. 面试常问问题

1. 问：Linux 目录结构 在嵌入式项目里有什么价值？
   答：它帮助程序更清楚地组织资源、通信或系统接口，最终服务可调试、可维护的项目实现。
2. 问：它和单片机 C 语言基础有什么关系？
   答：底层仍然离不开 C 的内存、指针、缓冲区和状态机，只是组织方式或运行环境不同。
3. 问：你如何证明自己真的用过？
   答：可以展示最小代码、调试日志、错误处理和项目复盘，而不是只说“我了解”。

如果项目只是学习项目，要明确写“个人项目”或“课程外实践”，不要写真实公司或客户信息。

## 9. 小练习

## 10. 小结

Linux 目录结构 的基础版学习重点是建立工程视角。你要知道它是什么、为什么项目需要、代码怎么起步、问题怎么调、简历怎么讲。后续精修时，再补更完整的实验步骤和项目代码。
