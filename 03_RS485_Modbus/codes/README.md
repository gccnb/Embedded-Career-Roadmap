# RS485/Modbus 示例代码说明

这个目录放的是 `03_RS485_Modbus` 模块配套的教学示例代码。它们不依赖具体芯片库，不绑定真实设备，也不代表任何公司或客户项目协议，只用于帮助初学者把文档里的概念和 C 语言代码对应起来。

涉及真实 RS485 模块、控制卡、驱动器、传感器或端子接线时，必须以芯片手册、模块手册、设备手册、原理图和实测结果为准。这里的代码只演示软件流程，不提供真实硬件接线结论。

## 代码文件说明

### `rs485_frame_demo.c`

教学目的：

- 模拟 RS485 自定义协议接收；
- 使用 `#` 作为帧尾；
- 使用 `rxBuffer`、`rxIndex`、`rxFlag`；
- 主循环处理完整帧；
- 收到 `$MODWA#` 后模拟回发。

它适合刚学串口中断接收的同学。重点不是 RS485 电气层，而是“中断只收字节，主循环处理完整帧”的思路。

### `modbus_crc16.c`

教学目的：

- 实现 Modbus RTU CRC16；
- 演示 03 功能码请求帧的 CRC 计算；
- 提供接收帧 CRC 校验函数。

阅读时要特别注意：Modbus RTU 帧尾 CRC 是低字节在前、高字节在后。很多通信问题不是算法不会写，而是高低字节顺序、漏算字节、把 ASCII 字符串当十六进制字节搞混。

### `modbus_rtu_demo.c`

教学目的：

- 模拟 Modbus RTU 从机解析流程；
- 支持 03 读保持寄存器；
- 支持 06 写单个寄存器；
- 使用模拟数组作为保持寄存器；
- 不依赖具体硬件。

它适合配合项目实战文档阅读。你可以把它看成“协议层最小闭环”：接收请求、检查地址和 CRC、判断功能码、访问模拟寄存器、生成响应。

## 建议练习方式

1. 先逐行阅读代码，不急着移植到单片机。
2. 手写一帧 03 请求，尝试算出 CRC，再和 `modbus_crc16.c` 输出结果对比。
3. 修改 `modbus_rtu_demo.c` 里的模拟寄存器初值，观察 03 读请求的响应变化。
4. 故意改错 CRC 或寄存器地址，观察代码如何处理异常。
5. 把代码流程改写成面试回答：输入是什么、处理步骤是什么、输出是什么、怎么调试。

## 可选编译检查

如果你的电脑上安装了 GCC，可以在本目录下做最基础的语法检查。

Windows 可以运行：

```bat
build.bat
```

Linux、macOS 或 GitHub Actions 可以运行：

```bash
make
```

也可以手动执行：

```bash
gcc -Wall -Wextra -c rs485_frame_demo.c
gcc -Wall -Wextra -c modbus_crc16.c
gcc -Wall -Wextra -c modbus_rtu_demo.c
```

如果没有 GCC，也不影响学习。你可以先把这些文件当作“可读的教学代码”，重点理解协议流程和调试思路。仓库中的 `.github/workflows/c-code-check.yml` 会在 GitHub 上对这些示例做最小编译检查。
