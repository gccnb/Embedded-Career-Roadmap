# RS485 与 Modbus 总览

## 1. 本节要解决什么问题

很多初学者会把 UART、RS232、RS485、Modbus 混在一起。比如面试官问“RS485 是不是协议”，有些同学会直接回答“是”。这个回答不准确。

本节要解决三个问题：

- RS485 是物理层通信方式，不是通信协议；
- UART、RS232、RS485、Modbus RTU 分别处在什么位置；
- 为什么嵌入式项目、Qt 上位机和工业控制场景经常把 RS485 与 Modbus RTU 放在一起。

先记住一句话：UART 管字节收发，RS485 管电气传输，Modbus RTU 管报文含义。

## 2. 基本概念

UART 是单片机内部常见的串口外设，它按照波特率、数据位、校验位、停止位发送和接收字节。它更像 MCU 里的一个“字节收发模块”。

RS232 和 RS485 是串口通信常见的电气接口方式。它们关心的是电平、线缆、抗干扰、传输距离和连接方式。

Modbus RTU 是通信协议。它规定一帧数据里地址码、功能码、数据区、CRC 怎么组织，主站和从站如何理解这些字节。

| 名称 | 主要层次 | 解决的问题 | 初学者容易误解 |
| --- | --- | --- | --- |
| UART | MCU 外设/串行收发逻辑 | 按指定格式收发字节 | 以为 UART 就等于完整通信系统 |
| RS232 | 电气接口 | 点对点串口电平传输 | 以为它适合长距离工业总线 |
| RS485 | 电气接口/物理层 | 差分、抗干扰、多点总线 | 以为它是协议 |
| Modbus RTU | 通信协议 | 规定报文格式和寄存器读写 | 以为只要接线对就自动会 Modbus |

RS485 常跑 Modbus RTU，是因为 RS485 适合工业现场的总线传输，而 Modbus RTU 提供了一套通用的主从报文规则。

## 3. 为什么嵌入式项目需要它

嵌入式项目不是只让单片机自己跑，还经常要和外部设备通信。比如抽象工业控制场景中，主控制板可能要读取传感器状态、给驱动器下发参数、向 Qt 上位机上传日志。

如果你只会 UART 发送字符串，项目会停留在“能发几个字节”。如果你理解 RS485 和 Modbus RTU，就能进一步回答：

- 为什么现场通信要用差分总线；
- 为什么主站要轮询从站；
- 为什么要有地址码和功能码；
- 为什么接收后要校验 CRC；
- 为什么 Qt 上位机要显示原始十六进制报文。

这些内容都很贴近嵌入式软件面试。面试官听到你能把“物理层、协议层、调试层”分开讲，就会知道你不是只背了一个关键词。

## 4. 工程使用场景

一个典型学习项目可以这样设计：

```mermaid
flowchart LR
    A["Qt 上位机\n串口配置/报文显示/日志"] --> B["USB-RS485 模块"]
    B --> C["RS485 A/B 总线"]
    C --> D["单片机控制板\nUART + RS485 收发器"]
    D --> E["抽象传感器/驱动器/IO 模块"]
```

这个图只表达通用工程链路，不代表任何真实公司项目。实际接线时，A/B 线定义、屏蔽层、终端电阻、共地方式、供电方式、端子编号必须以对应芯片手册、模块手册、原理图和实测结果为准。不同厂商可能把 A/B 标法写得不一样，不能凭经验直接接。

典型使用场景如下：

| 场景 | RS485 的作用 | Modbus RTU 的作用 | 求职时怎么讲 |
| --- | --- | --- | --- |
| 上位机调试控制板 | 负责总线电气传输 | 读写寄存器、解析响应 | 能讲清楚 Qt 串口日志和报文解析 |
| MCU 读取传感器 | 抗干扰、较远距离通信 | 读取测量值寄存器 | 能讲清楚地址、功能码、CRC |
| 控制器访问驱动器 | 多设备总线连接 | 参数读写和状态查询 | 能讲清楚超时、异常响应 |
| 实验室协议项目 | 建立可复现链路 | 做标准协议训练 | 能形成简历项目闭环 |

## 5. 代码示例

下面用教学示例构造一帧 Modbus RTU 读保持寄存器请求。这里的地址只是协议学习用例，不代表任何具体设备寄存器地址。真实设备的寄存器地址必须查协议手册。

```c
unsigned short modbus_crc16(const unsigned char *data, unsigned short length);

static void write_u16_be(unsigned char *buf, unsigned short value)
{
    buf[0] = (unsigned char)((value >> 8) & 0xFF);
    buf[1] = (unsigned char)(value & 0xFF);
}

unsigned short build_modbus_read03(unsigned char *frame,
                                   unsigned char slave_addr,
                                   unsigned short start_addr,
                                   unsigned short reg_count)
{
    unsigned short crc;

    frame[0] = slave_addr;
    frame[1] = 0x03;
    write_u16_be(&frame[2], start_addr);
    write_u16_be(&frame[4], reg_count);

    crc = modbus_crc16(frame, 6);
    frame[6] = (unsigned char)(crc & 0xFF);
    frame[7] = (unsigned char)((crc >> 8) & 0xFF);

    return 8;
}
```

这段代码体现了三件事：

- UART 最终发送的是 `frame` 里的字节；
- 如果走 RS485，需要在发送前后控制收发方向；
- Modbus RTU 规定了字节含义和 CRC 放置方式。

## 6. 常见错误

| 错误 | 后果 | 正确理解 |
| --- | --- | --- |
| 把 RS485 当成协议 | 面试时概念层次混乱 | RS485 是电气接口，Modbus RTU 才是协议 |
| 只会发送字符串 | 无法处理真实设备寄存器读写 | 要能构造和解析二进制帧 |
| 不保存原始报文 | 调试时无法定位功能码、CRC、长度问题 | 上位机和下位机都要保留十六进制日志 |
| 不查设备手册 | 可能接错线、读错寄存器 | 接线和寄存器必须按手册、原理图和实测确认 |
| 不处理超时 | 主站可能一直等待 | 通信必须有超时和错误统计 |

## 7. 调试方法

建议按层排查，不要一上来就怀疑代码全错：

1. 物理层：确认电源、地、A/B、终端电阻、屏蔽和 RS485_EN/DE/RE。
2. 串口参数：确认波特率、数据位、停止位、校验位一致。
3. 方向控制：确认发送时切到发送模式，发送完成后切回接收。
4. 报文格式：确认地址码、功能码、数据区长度正确。
5. CRC：确认低字节在前，高字节在后。
6. 上位机日志：保存发送帧、接收帧、时间戳、错误原因。

如果使用真实控制卡、驱动器、传感器或转换模块，所有接线和端子定义都要回到对应芯片手册、模块手册、原理图和实测结果。

## 8. 面试常问问题

1. 问：RS485 是通信协议吗？
   答：不是。RS485 是电气接口或物理层通信方式，解决差分传输、抗干扰和总线连接问题。Modbus RTU 才是协议，规定报文格式和数据含义。

2. 问：UART、RS232、RS485 有什么区别？
   答：UART 是 MCU 内部的串口收发外设；RS232 和 RS485 是外部电气接口。RS232 多用于点对点通信，RS485 用差分信号，更适合工业现场和多点总线。

3. 问：为什么 Modbus RTU 常跑在 RS485 上？
   答：Modbus RTU 是主从式二进制协议，适合串行链路；RS485 抗干扰、距离较远、可以挂多个节点，所以两者在工业控制中经常搭配。

4. 问：调试 RS485/Modbus 没响应，你会怎么查？
   答：先查供电、A/B、共地和终端电阻，再查波特率、校验位、从站地址，然后看 DE/RE 方向时序，最后逐字节核对功能码、数据区和 CRC。

5. 问：Qt 上位机在这个项目里有什么价值？
   答：Qt 上位机可以配置串口参数、发送 Modbus 帧、显示原始十六进制响应、保存日志，帮助下位机协议联调，也能作为简历项目展示界面。

## 11. 小结

RS485 与 Modbus RTU 是嵌入式求职里非常适合做项目主线的一组知识。你要能讲清楚：RS485 是物理层，不是协议；UART、RS232、RS485 各自解决什么问题；Modbus RTU 为什么要有地址码、功能码、数据区和 CRC。

真正的工程能力不是“我会 RS485”，而是“我能把硬件链路、串口参数、方向控制、协议帧、CRC 校验和上位机日志一起调通并讲清楚”。
