# 自定义协议设计

## 1. 本节要解决什么问题

本节要解决的问题是：当串口或 RS485 已经能收发字节后，如何规定“这些字节到底表示什么意思”。

很多同学做串口项目时，一开始会写 `$OPEN#`、`$STOP#` 这种字符串命令。这种方式适合入门，但如果命令变多、数据变长、需要校验和异常处理，就必须设计更清晰的通信协议。

自定义协议是学习 Modbus RTU 前非常有价值的一步。它能帮你理解帧头、长度、命令字、数据区、校验、超时、重发和状态机解析。学完这部分，再看 Modbus RTU 的地址码、功能码、数据区和 CRC，就不会觉得它是凭空出现的复杂格式。

## 2. 基本概念

通信协议就是通信双方都遵守的数据格式约定。串口、RS485 只负责把字节传过去；协议负责说明每个字节的意义。

一个常见自定义协议帧可以设计成：

| 字段 | 长度 | 作用 |
|---|---:|---|
| 帧头 | 1 到 2 字节 | 标记一帧开始，如 `0xAA 0x55` |
| 长度 | 1 字节 | 表示后续数据区长度 |
| 命令字 | 1 字节 | 表示操作类型，如读状态、写参数 |
| 数据区 | N 字节 | 携带参数或状态数据 |
| 校验 | 1 到 2 字节 | 判断数据是否出错 |

示例：

```text
AA 55 03 10 01 02 16
```

可以解释为：

- `AA 55`：帧头；
- `03`：数据区长度为 3；
- `10`：命令字；
- `01 02`：参数；
- `16`：简单累加校验。

这个示例只用于教学，不代表真实设备协议。真实设备协议必须来自公开协议文档、厂家手册或自己项目中可公开的设计说明，不能凭空编造为某设备协议。

## 3. 工程用途

自定义协议常用于单片机和上位机、单片机和模块、控制器和执行单元之间的简单通信。它比直接发字符串更清楚，也比一开始就上 Modbus 更适合入门。

典型用途：

- Qt 上位机发送命令，单片机执行模拟动作；
- 单片机上传状态字、ADC 采样值、错误码；
- RS485 多节点项目中做简单地址和命令分发；
- 为后续 Modbus RTU 帧解析训练缓冲区和状态机思维。

工程里设计协议要考虑三件事：能不能解析、出错能不能发现、后续能不能扩展。只要协议变复杂，就不能只靠 `#` 判断结尾，要考虑长度、校验、超时和状态机。

涉及真实控制卡、驱动器、传感器、端子或设备内部协议时，必须以数据手册、协议手册、原理图和实测结果为准。公开资料库中只写抽象学习协议，不写真实公司或客户协议细节。

## 4. 简单代码或伪代码

下面示例演示一个最小二进制协议解析流程。

```c
#include <stdint.h>
#include <string.h>

#define FRAME_HEAD1     0xAA
#define FRAME_HEAD2     0x55
#define RX_MAX_LEN      64
#define CMD_READ_STATE  0x10
#define CMD_SET_PARAM   0x20

typedef enum {
    PARSE_WAIT_HEAD1 = 0,
    PARSE_WAIT_HEAD2,
    PARSE_WAIT_LEN,
    PARSE_WAIT_PAYLOAD,
    PARSE_WAIT_CHECK
} ParseState;

static ParseState parseState = PARSE_WAIT_HEAD1;
static uint8_t payload[RX_MAX_LEN];
static uint8_t payloadLen = 0;
static uint8_t payloadIndex = 0;

static uint8_t calc_sum(const uint8_t *data, uint8_t len)
{
    uint8_t sum = 0;

    for (uint8_t i = 0; i < len; i++) {
        sum += data[i];
    }

    return sum;
}

void protocol_input_byte(uint8_t byte)
{
    switch (parseState) {
    case PARSE_WAIT_HEAD1:
        if (byte == FRAME_HEAD1) {
            parseState = PARSE_WAIT_HEAD2;
        }
        break;

    case PARSE_WAIT_HEAD2:
        parseState = (byte == FRAME_HEAD2) ? PARSE_WAIT_LEN : PARSE_WAIT_HEAD1;
        break;

    case PARSE_WAIT_LEN:
        payloadLen = byte;
        payloadIndex = 0;
        if (payloadLen == 0 || payloadLen > RX_MAX_LEN) {
            parseState = PARSE_WAIT_HEAD1;
        } else {
            parseState = PARSE_WAIT_PAYLOAD;
        }
        break;

    case PARSE_WAIT_PAYLOAD:
        payload[payloadIndex++] = byte;
        if (payloadIndex >= payloadLen) {
            parseState = PARSE_WAIT_CHECK;
        }
        break;

    case PARSE_WAIT_CHECK:
        if (calc_sum(payload, payloadLen) == byte) {
            protocol_handle_frame(payload, payloadLen);  /* 伪函数：处理完整帧 */
        }
        parseState = PARSE_WAIT_HEAD1;
        break;
    }
}
```

这段代码的重点是状态机。中断或接收函数只把字节交给解析器，解析器逐步判断帧头、长度、数据区和校验。真正的命令处理放在 `protocol_handle_frame()` 里。

## 5. 常见错误

1. 没有长度字段。只靠帧尾判断，一旦数据区里也出现帧尾字符，解析会混乱。
2. 没有校验。线路干扰或接收丢字节时，程序可能执行错误命令。
3. 在串口中断里直接处理复杂命令。中断应尽量短，复杂解析放到主循环或任务。
4. 没有超时机制。收到半帧后一直等待，后续帧可能被粘在一起。
5. 命令字没有规划。今天写 `0x01`，明天又写 `0x01`，后续维护困难。
6. 把学习协议写成真实设备协议，导致公开资料边界不清。

## 6. 调试方法

调试自定义协议要保存原始字节，不要只看解析结果。

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| 一直解析不到帧 | 帧头错、长度错、接收丢字节 | 打印 RX 十六进制原始数据 |
| 偶发命令错误 | 没有校验或校验范围错 | 手动计算校验并对比程序结果 |
| 收到半帧后卡住 | 没有超时复位状态机 | 加入帧接收超时 |
| 多帧连续发送出错 | 缓冲区处理不完整 | 连续发送测试帧，检查状态机复位 |

建议调试步骤：

1. 先固定发送一帧最短命令，确认帧头和长度能识别。
2. 再加入数据区，确认长度和索引不会越界。
3. 再加入校验，确认校验覆盖范围一致。
4. 故意发错帧头、长度和校验，验证程序不会误执行命令。
5. 最后再接 RS485 链路，并结合方向控制和串口日志排查。

## 7. 面试常问问题

1. 问：为什么需要自定义协议？
   答：串口和 RS485 只传字节，不说明字节含义。自定义协议规定帧格式、命令字、数据区和校验，方便双方正确解析。

2. 问：协议里为什么要有长度字段？
   答：长度字段能明确数据区有多少字节，避免只靠帧尾导致二进制数据解析不稳定，也方便连续帧处理。

3. 问：为什么需要校验？
   答：校验用于发现传输错误或解析错误。简单项目可用累加和，工业协议常见 CRC。

4. 问：协议解析为什么常用状态机？
   答：串口是字节流，数据不是一次性完整到达。状态机可以逐字节推进解析流程，处理半帧、错帧和连续帧。

5. 问：自定义协议和 Modbus RTU 有什么关系？
   答：自定义协议是自己定义帧格式；Modbus RTU 是标准协议，有固定地址码、功能码、数据区和 CRC。学习自定义协议有助于理解 Modbus 的设计。

## 8. 简历表达方式

> 设计并实现串口自定义协议解析流程，包含帧头、长度、命令字、数据区和校验字段，使用状态机逐字节解析接收数据，并通过错误帧、半帧和连续帧测试验证协议稳定性。

如果项目中确实结合了 RS485 和 Qt 上位机，可以补充“配合上位机保存 TX/RX 原始日志完成联调”。

## 10. 小结

自定义协议设计的核心不是“随便定几个字节”，而是让通信双方能稳定、可调试、可扩展地理解数据。掌握帧头、长度、命令字、数据区、校验、超时和状态机解析后，再学习 Modbus RTU 会更顺畅，也更容易在面试中讲清通信项目。
